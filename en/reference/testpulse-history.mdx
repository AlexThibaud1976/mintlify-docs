The versions below are those of **TestPulse**, the extension TestPulse Studio comes from — not those of TestPulse Studio, whose milestones are in the **What's New** tab. The dashboard widget they mention is not part of TestPulse Studio.

**v2.61.1 — 2026-08-19**
- Fixed: the hub update banner could show raw Markdown asterisks and run up to four lines long — it read the What's New panel's own item text verbatim, a field written for documentation, not a single banner line. A dedicated, optional banner sentence replaces it; missing in the current language shows no second line rather than falling back to the other language or to that item text. The What's New panel itself is unchanged.

**v2.61.0 — 2026-08-19**
- Repository: the "Plans & suites" tree-bootstrap source is retired — Area Paths is now the only source, so the dialog opens straight on the numeric preview and confirmation, no source picker. On a real, plan-heavy project the plan/suite source produced a tree several times more crowded than Area Paths, from far more requests, and a single-parent tree can't structurally mirror plans that share cases — optimizing those requests would still have produced the same crowded tree. Nothing already bootstrapped from it is touched. The Coverage Builder is unaffected — it shares the underlying suite-lookup call, which stays exactly as it was.
- Repository: four evolutions to give the tree room to breathe. Row actions (rename, add, delete, generate a plan) now stay hidden until you hover, select, or keyboard-focus a row, with their space always reserved so nothing shifts on appearance. Long folder names truncate to one line with the full name in a tooltip instead of wrapping. A draggable, keyboard-adjustable divider (bounded, remembered per user) lets you resize the tree against the case list. With nothing selected, the tree takes the full width instead of a "0 selected" panel eating half the screen.

**v2.60.1 — 2026-08-19**
- Hub update banner: a small info banner above your reports names the new version and links to What's New whenever a major or minor update lands (silent on a patch-only bump, including this one — no launch version can ever show it on its own release). Closing it is per-user (ADO Extension Data, User scope) and never affects anyone else on the project. Zero new ADO call, zero new dependency.

**v2.16.3 — 2026-06-26**
- Fixed (follow-up to 2.16.2): the Quality overview dashboard widget and its configuration blade now load on Azure DevOps Services. The fully-qualified contribution ids are now registered before SDK init, so they exist when the cloud host does its one-shot lookup — the 2.16.2 post-handshake re-registration arrived too late. Short-id registration (on-prem Server 2022.1) and the diagnostic log are unchanged. No new dependency, no ADO call/scope, manifest untouched.
- 741 Vitest tests (4 new)

**v2.16.2 — 2026-06-26**
- Fixed: the Quality overview dashboard widget now loads on Azure DevOps Services. The cloud host resolves contributions by their fully-qualified id, so after the SDK handshake the widget re-registers under that exact id (in addition to the short id). Belt & braces and fully additive — the short-id registration is unchanged, so the on-prem path (Server 2022.1) is not affected. A diagnostic log reports the resolved contribution id. No new dependency, no ADO call/scope, manifest untouched.

**v2.15.0 — 2026-06-24**
- Scale profiles & risk-based weighting: (A) a **project-level** quality scale profile (Strict / Standard / Rodage, bounded tuning, off-preset = Custom) stored at project scope so everyone scores a report identically; Standard = today’s scale exactly. (B) An optional **risk-based weighting** toggle showing a **weighted confidence** beside the badge (report, widget tile, PDF) — execution/coverage weighted by test-case priority and US risk/story points via additive tiers, never multiplicative. The flat A–E score is never altered (toggle off ⇒ identical output); hollow dimensions auto-disable; no extra ADO call.

**v2.14.0 — 2026-06-24**

Highlighting of already-computed data: no new metric, the A–E score is unchanged, no extra network call. "Blocking" uses the single definition; uncovered requirements are derived at build time (suite-based, 100 % coverage ⟺ empty list). Hidden when not evaluated, explicit empty state, historical reports tolerated.
