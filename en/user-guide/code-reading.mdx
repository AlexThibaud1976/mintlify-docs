**Where.** **Read the code** is at step 0 **Requirement** of **Conception** and in the **Exigence** tab of a work item. Nothing is read when the screen opens.

**Before.** Your organization approves the code permissions once (an organization administrator, in Organization settings › Extensions), and a project administrator checks **Source code excerpts** in the data sent to the model (*AI assistant › Functions and data*) — it is off by default; off, Studio makes no call to the code.

**What is read.** The pull requests, commits and branches linked to the story and to its child tasks (Azure Repos; GitHub links are not read in this version). Each link shows what was read (title and state of a pull request, repository, number of files) or why it was not: the organization has not approved code reading yet, you do not have access to the repository, the repository or version was not found.

**Before sending.** The list shows each file — repository, version, category (validators, routes, screens, tests, other), whole or changed parts, size, tokens, the link that brought it — and the estimated total. Untick what must not be sent. Lock files, generated, minified and binary files are always excluded; **a secret file is never offered**. Caps (files, characters per file, in total) are set in **Requirements and design**.

**Then.** The ticked files join the next assessment of the requirement: the criteria that depend on code can be verified. Nothing is kept once the page is closed. **Compare with the code** comes in a future version. Azure DevOps Server: code reading is not validated.
