The **Repository** hub tab is a free, **project-shared** folder tree to organise and find your Azure DevOps Test Cases — Xray-style — without ever touching ADO. It **stores references only** (a test case id), never a copy of its content; title and steps are always re-read live from Azure DevOps. **Zero ADO write**, ever.

- **Folders** — create, rename, delete and move folders at any depth, by **native drag & drop** or the row buttons. Deleting a folder (with confirmation if it or its descendants hold test cases) sends its cases back to **Unclassified** — nothing is silently lost, and a folder can never be moved into one of its own descendants.
- **Rank a test case** — drag a case onto a folder, or use the **"Move to…"** menu on its row — a fully **keyboard-accessible equivalent** to drag & drop, so ranking never depends on a mouse. A case lives in **one folder at most**; dropping it again just moves it, and **Remove from folder** sends it back to Unclassified.
- **Search & Unclassified** — search by **title, id or tag** (accent- and case-insensitive) across the whole project; the **Unclassified** node is the project’s test-case universe minus whatever is already ranked, **always recomputed, never stored**.
- **Used in** — expand a case to see **"Used in N location(s)"**, a plan › suite list from the same reader as the work-item coverage tab. **No execution status is ever shown here** — that lives on the coverage tab, a distinct axis.
- **Not in any plan** (formerly "ADO orphans") — this node runs an **explicit, on-demand scan** (never automatic) for cases that sit in no plan or suite at all, with progress, cancel and a **cached, timestamped result** you can re-run. A case here can be ranked into a folder like any other case — being ranked and being unplanned are two **orthogonal** facts (that status stays ADO-computed).
- **Bootstrap the tree** — on a real project with hundreds or thousands of cases, nobody ranks them one by one. Seed the tree automatically from **Area Paths** — a **numeric preview** (folders to create, folders reused, cases to rank, cases already ranked and left untouched) is shown before anything is written, cancellable. **Purely additive**: existing folders are reused by trimmed name, nothing is ever renamed, moved or deleted, and an already-ranked case is never re-ranked. Fully **idempotent** — running it again only picks up what’s new. On a real, plan-heavy project, seeding from the plan/suite hierarchy instead used to produce a tree several times more crowded than the same project’s Area Paths, from far more requests — a plan/suite tree can’t structurally mirror plans that share cases with a single-parent folder, so that path has been retired; nothing already built from it is touched.
- **Bulk actions** — tick cases across the list (the selection survives scrolling, resets on folder/filter change), **select all** scoped strictly to what the current filter shows, then **assign to a folder** or **remove from folder** in **one atomic write** for the whole batch, with an exact summary (assigned / moved from elsewhere / already there).
- **Readability** — each folder shows its case count **including descendants** (Xray-style); a **flat view** toggle lists every ranked case with its full folder path for finding one without navigating the tree (view choice remembered); sibling folders sharing a trimmed, case-insensitive name get a non-blocking warning (creating/renaming stays allowed).
- **Rank** — reorder cases inside a folder by drag & drop or the keyboard (move up/down); each folder has a sort mode (by id, by title, or manual) — the first manual reorder switches it to manual, and switching back to an automatic sort requires an explicit confirmation so a manual order is never silently discarded.
- **Shared & safe for teams** — the tree lives in the project’s own Extension Data (shared by everyone on the project, isolated from other projects) with **optimistic concurrency**: two people organising at once never silently overwrite each other, and an **"updated by X · refresh"** banner tells you when someone else just changed it. At load, titles are refreshed and a case **deleted in Azure DevOps** is flagged **missing** (never silently dropped) — you can remove that stale reference yourself.
- **Reliability fixes** — the tree is now stored as a **single atomic document** (one folder-per-document plus a separate index was the original design; a case move or a cascading delete could previously leave a partial state on failure — no longer). A folder without a stored `parentId` no longer makes the tree render empty. Re-running an orphan scan, or refreshing after any change, no longer fails with a version conflict. On Azure DevOps Services (cloud), the tab could occasionally show 403 errors on the underlying work-item query — the base URL resolution is now robust in both cloud and on-premises. Any real read failure now shows an explicit error banner instead of silently looking like an empty project.
- **Readable, collapsible tree** — folders now carry a **status icon** (closed/open), a **chevron** to fold or unfold a branch (separate from selecting — clicking it never changes what you're looking at), and thin **indentation guides** so a deeply nested folder still reads at a glance. Folders start **collapsed**, Xray-style — expand what you need, and it **stays that way** the next time you open the tab, remembered **per user**. Selecting a folder or creating one inside a collapsed parent opens it automatically so you're never left looking at nothing, and dragging a case over a collapsed folder for a moment opens it too — dropping on a closed folder always worked and still does. Folding never changes what's in a folder or its case count; it only limits what's drawn on screen. **Unclassified** and **Not in any plan** now sit inside the same keyboard-navigable list as your folders, each with its own icon, italic label and a live count (the "Not in any plan" count only appears once you've actually run the scan, and turns amber only when it finds something).
- **Room to breathe** — a folder's four row actions (rename, add, delete, generate a plan) now stay hidden until you hover the row, select it, or focus it with the keyboard, instead of crowding every row all the time; the space they take up is always reserved, so nothing shifts when they appear. A long folder name is now truncated to one line with its full name available as a tooltip, instead of wrapping onto two. Drag the **divider** between the tree and the case list to resize either one (bounded, so neither can be squeezed away entirely) — it's also keyboard-focusable and adjustable with the arrow keys, and your chosen width is **remembered per user**. Select nothing at all (or deselect what's selected) and the tree takes the **full width**, since there’s nothing yet to show on the other side; picking a folder, Unclassified or Not in any plan brings the case list back at the width you last chose.
