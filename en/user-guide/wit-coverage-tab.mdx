The **"Couverture" tab** appears on a **User Story / PBI** work item (auto-placed, mounted on first click). It is **read-only** and independent of published reports.

- **Headline** — two pills, **Coverage** (are there linked test cases?) and **Depth** (do those tests have real steps?), shown instantly.
- **Detail** (auto-loaded) — an **execution verdict** banner (**Passed / Not OK / Not Run / Not covered**), depth findings, a numeric summary, and each linked test’s latest pass/fail with the **bug** behind a failure.
- **Config-correct latest** — when a test case covers **several sibling stories that only differ by test configuration** (e.g. Italy / Singapore / Korea), the **"Last run"** shown here is resolved from **this story’s own configuration** (its requirement-based suite), never a sibling’s more recent run. A story without a requirement-based suite keeps the previous behaviour (latest across all configurations). The **run link** now opens the **exact result** (when known); the scope selector labels read **"plan · config"** when a configuration is known.
- **Scope selector** — the **scope selector** is shown **whenever the story is covered**: **Latest (all plans)** (default) or a **specific test plan**. It frames the pass/fail on the chosen scope (masking out-of-plan tests), is remembered per work item, and switches **instantly in memory** (no new read). With a single plan it still shows *Latest (all plans)*, so results are always explicitly framed as the **latest execution**.
- **Clickable #ID** — each linked test shows a **clickable #ID** that opens the **work item** in a new tab.
- **Sortable columns** — click any of the five headers (**#, Test, Outcome, Last run, Bug**) to sort the table; click the same header again to reverse the direction. Outcome sorts attention-first (failures on top), Test by name. Your sort is remembered per work item and the default order is unchanged.
- **Open run / open plan** — an **executed** row shows a single link that opens its **test run** (Last run column); when a **specific plan** is scoped, an **Open plan** link sits next to the scope selector and targets the **exact executed suite** when one can be derived (never a blank plan page). Both are routed through Azure DevOps itself rather than the tab’s own popup, so they also open reliably inside the sandboxed on-prem work-item form (no more blank tab on ADO Server on-prem); they open in a new tab and are portal navigations (no new read).
- **Modified after last run** — when the story was **changed after the most recent run of its linked tests**, a conditional warning badge tops the panel. It is computed on **all** results (plan-independent, like the header), never shows for a never-run story, and disappears as soon as a newer run exists. Same data the tab already reads — no added call.
- **What changed since the last run** — the badge above now carries a **"Show detail"** button. Expanding it fetches (once, lazily — never on page load) the story’s changes since that run and lists the impacted **business fields** (Acceptance criteria, Description, State, Priority, Iteration, Tags — Title too) as **before → after**, with the **added wording highlighted** on rich fields (a small home-made word diff, no library) and a **"feeds depth analysis"** badge on Acceptance criteria / Description changes. A separate block lists **attachments added/removed** since the run. Collapsing and re-expanding never re-fetches.
- **Exploratory sessions, mentioned (2.58.0)** — when this requirement has one or more **closed** exploratory sessions, the depth findings gain an informational line stating exactly how many, naming the **Exploration** tab (right next to this one — Azure DevOps doesn't let an extension jump you there programmatically, so the mention names it instead of linking it). It never affects the **Coverage** pill, the execution verdict, the pass rate or the quality score — an exploration credits nothing there, by design; it only tells you the exigence wasn't untested, just untested *by a test case*. Loaded in the background, after the pills and verdict are already on screen — a read failure simply omits the line, never a "0" that would claim no exploration ever happened.

Coverage, Depth and the bug list stay plan-independent. No new API call, scope or dependency beyond the one described above; it never writes.
