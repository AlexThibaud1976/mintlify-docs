**Where and who.** The **Usage and telemetry** page is in **Project settings › Extensions › TestPulse Studio**, under *Tracking*, reserved for project administrators. A member does not see it and never reads these counters.

**What is counted.** Each use adds one to a counter of the day: reports generated (in total) and profiles applied (by profile identifier), exports by format, AI functions by function (campaign analysis, free question, coverage axes, test classification, test model, case writing, designed cases check) — succeeded, failed and cancelled by the user, with their tokens, each function apart (the test model apart from case writing, the free question apart from campaign analysis; counters older than 0.1.122 kept them with case writing and campaign analysis, and are not split afterwards); "launched" is their sum, computed on screen —, designed cases — generated, checked, written to Azure DevOps, ignored at review — and the judge's issues, validated classifications, AI errors by code (the ones a member sees), and durations by range (under 2 s, 2 to 10 s, 10 to 30 s, 30 s and more). The events form a closed list: nothing else is counted. An AI function that fails counts as failed, and its error by code; one cancelled by the user counts as cancelled.

**Screens and features.** Each screen or tab a user opens (a click, a link — not a re-display, nor a screen's default tab, already counted by opening the screen; the page the project administration opens on and the panel a profile opens on do count, like the screen an area opens on), each completed action (a file produced, a successful write, a result displayed — never a mere click) and each load of an area (Insights, Coverage, Design, Tools, project administration) adds one, by identifier from a closed list. No user, no session identifier, no typed text, no filter value, no note or capture content.

**Second step (requirement, code, automated tests).** The counters also cover the features of the second step: four AI functions (requirement assessment and reassessment, improvement proposal, requirement ↔ code check, automated tests and the regeneration of one test), their screens and actions, and eleven tables of counts under closed lists — Definition of Ready verdicts, verdict rules triggered, assessment checks, PO questions by priority, sources not read by reason, losses detected in proposals, story writes refused, requirement ↔ code gaps, automated tests drafted and delivered by framework × language combination, drafted tests by status. Never a score, an identifier, a repository, branch or file name, a code excerpt or a typed text.

**Where they are kept.** In the project storage (Extension Data, document `tpai-usage`), grouped: at most one write per minute and per session, never blocking — a write that fails is ignored, with no message. 90 days are kept day by day; older days are added up by month, and monthly totals older than 24 months are deleted. The document counts in the project storage gauge; when the quota is reached, the counters are no longer written and the page tells the administrator.

**No personal data.** No person's name or identifier, no organization, project or plan name, no work item title, no prompt or model answer, no URL, no key.

**The screen.** A period of 7, 30 or 90 days; tiles (reports, exports, AI functions with tokens, failures and cancellations, designed cases with the written / generated ratio, errors, screens and tabs opened); the **trend by day**, as bars (reports, AI functions, cases written); four tables shown — *AI functions* (launched / succeeded / failed / cancelled, with their tokens), *Errors by code*, *Exports by format*, *Definition of Ready verdicts* — and the other tables folded, among them the **Screens and features** family (screens and tabs, completed actions, sessions per area), each by its name — the identifier that is sent shows as a tooltip; **Export as CSV** (a local file, `Date;Family;Identifier;Label;Count`: the identifier and its name). On opening, the page first writes what was just counted on the page, so its own opening shows at once.

**Sending to the publisher — off by default.** An administrator can turn it on, seeing what is sent and what is never sent, with the exact list of fields; like every setting of the administration, the switch changes the draft, and **Save** in the banner applies it. **Preview next send…** shows the same tiles and tables for the days to send, and sends nothing; with no complete day to send, it says that today's counters will go tomorrow (if sending is on). What is sent: the schema version, an installation identifier (random, created on first activation, never derived from an Azure DevOps identifier), the extension version, the host type (cloud or Server, and the Server major version), the AI provider and, for each AI function turned on, the family of its model (`other` when the name is not recognised — never the model or deployment name), the interface language, and for each day not sent yet: the count per event, the tokens per AI function (test model and free question apart), the judge's issues, the errors per code, the durations per range, the profiles applied by identifier, the screens and tabs opened, the completed actions and the sessions per area (by identifier), the failed and cancelled AI functions by event, and the second-step counters (eleven tables of counts under closed lists). An unreadable counter document is set aside, never overwritten. **Never sent:** people, organization, project, plans, work items, prompts, model answers, API key, switch log. At most one send a day, from the Insights, Coverage and Design areas; a failed send is ignored and retried the next day — no member ever sees an error; after a long interruption, a send is capped in size and the remaining days leave with the next sends, and an instance with no outbound access simply keeps its counters. Turned off, nothing is sent any more; the identifier is kept so that turning it on again does not count twice. **Forget this installation…** (with confirmation) replaces it with a new one. Every switch is logged (author, date).

**In this version, sending is not configured:** the switch is disabled and says so; nothing is sent.
