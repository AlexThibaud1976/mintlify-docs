The **“Exploration” tab** on a User Story / PBI runs a full **exploratory testing session** from the story itself — the link to the story is implicit, nothing to install on the tester’s machine, and the tab now carries TestPulse Studio’s own visual identity end to end.

- **Past sessions, right where you'd look for them (2.58.0)** — open the tab on a requirement that's already been explored and its **closed sessions are listed above the start form** — a charter and a link to each one's tracking Task, opened the same sandbox-safe way as everywhere else in the tab. It never replaces or hides the start form; a requirement with no closed session yet looks exactly as it always has. None of this appears on the tracking Task itself, where the panel above already shows the one session that matters.

- **Start in one click** — a charter **pre-filled with the story title** (editable), an optional **timer** with **pause/resume** (a clear on-screen notice — plus a desktop notification when your browser allows it — when the timebox runs out), a free **campaign tag** (spaces become dashes; propagated to everything the session creates), and **area / iteration paths inherited from the story**, shown collapsed and ready to go — expand **Change scope** only if you need to override them. Tree pickers show a live result count while filtering. The session document is saved immediately. If the work item you're on is itself a session-record Task, a notice warns you before you start — starting here is probably not what you meant — but nothing is blocked, the form stays fully usable.
- **Timestamped notes** — type a note and press Enter; each entry shows its local time. The placeholder reminds the capture shortcut (**Ctrl+V** to paste, **Win+Shift+S** to capture any screen).
- **Paste a capture from anywhere** — copy a screenshot of **any application on any monitor** (desktop apps included) and press **Ctrl+V** in the notes field. The image opens in an **annotation editor**: arrow, rectangle, text, highlighter and **blur** (mask sensitive data — while you drag, a dashed frame tracks the cursor, and on release the preview shows the real blur itself, not a placeholder, painted the exact same way it will be at the final flatten — the blur stays **destructive** only at that last step), two explicit colours, undo. **Attach to session** flattens and uploads the PNG to Azure DevOps and adds it to the timeline (thumbnail + *annotated* badge); **Cancel uploads nothing**. Pasting plain text simply types the text — never an error.
- **Attach any file, or several at once (2.70.0)** — drag & drop files (a Win+G video, a log…) onto the timeline; each is uploaded under its own name and listed with its size. The drop zone follows the Import page pattern — a **2 px dashed border**, an icon, a title, a hint and a **Browse…** button, at least 100 px tall, and the same size throughout the session. While you drag a file, **the whole timeline panel becomes the target**: an overlay covers it, crossing an element inside does not make it flicker, and dragging selected **text** never raises it. A file released **beside** the panel is swallowed — the browser no longer opens it in the tab and your session stays on screen; that guard lives in this tab alone and leaves with it. **Browse…** opens the native picker, with **no type filter**: the size limit is Azure DevOps’s to enforce. Several files dropped together are uploaded **one after another**, with a progress line showing rank, total and current name, and a note you type while the batch is uploading is kept. A second drop during a batch is ignored without an error. If one file fails, the others stay attached and the message **names** the failed one with Azure DevOps’s own wording — nothing is rolled back; only a permission failure (401/403) stops the batch, raising the re-approval banner.
- **Fix a note, correct a caption, or drop something you did not mean to keep** — while the session is still active, hovering a note or capture reveals an edit and a delete icon. Editing a note fixes a typo without touching its timestamp (the trace of when, never of the correction) and lets you reclassify it — observation / question / idea / anomaly — at the same time; leaving the text empty is refused with a clear reason, never silently emptied. A capture caption is editable the same way — the image itself never is, once attached it is final, and the thumbnail says so. Deleting always asks for confirmation, and that confirmation is explicit: the underlying file stays in Azure DevOps, only its mention on the timeline goes away — TestPulse Studio never calls a delete API against your tenant. A work-item entry can never be edited or removed — it is proof a Bug/Task/Test Case genuinely exists in Azure DevOps — and once a capture has actually been attached to one, its delete icon locks too, naming that work item right in the tooltip; a capture from a session saved before this feature existed locks the same way rather than guessing it is safe to remove. None of this is available once the session has ended — a closed, abandoned or incomplete session's trace never changes again.
- **Captures can say what they show (2.58.0)** — when annotating a pasted capture (or from the timeline afterwards), declare whether it shows a **step to perform** or a **result obtained** — or leave it unspecified, the default and never guessed. A test case generated from the notes attaches each capture to the step born from the note right before it (so it lands on the correct step in Azure DevOps, not just on the work item); a capture marked *result obtained* also fills that step's expected result. A session with no typed captures generates the exact same test case as before this feature. The PDF report carries the same distinction as a small caption next to each typed capture; an untyped one renders exactly as before.
- **Create work items in two fields, during the session or after it ends** — *Create bug / work item* opens a panel with just a **title** (pre-filled with your last note) and a **severity**. Everything else is injected, **visible and editable**: repro steps generated from your timestamped notes, every **capture and file** to attach in one list (all resolvable ones ticked by default; one whose upload hasn't caught up yet shows disabled with its reason instead of silently disappearing), links to the story and the session, and the session classification with a collapsed **Change classification** override. **Task** and **Test case** variants reuse the same panel (a test case can optionally generate its steps from the notes, and now correctly shows as **testing** the story rather than the reverse — this applies to newly created links only, existing ones are never rewritten). The session stays active and the timeline logs *Bug #N created*. **The same gesture is available after the session has ended, too** — open the session's tracking Task and it's right there, reading the closed session back from storage — found through the session identifier the Task carries in its `explore-session:` tag, so the export and creation gestures work there even if the hub list missed an update. A Task whose session was run in the Explore tab of TestPulse says so and sends you to that tab: that session lives in TestPulse's storage, not in TestPulse Studio's. Nothing about creating during an active session changes.
- **End or abandon** — *End session* (with confirmation) archives the session as a **Task tagged `exploratory-session`** (+ campaign tag), carrying the full report — charter, duration, counters, chronological timeline — and every relation: the story, each capture and file, each created work item. A small, entirely **optional** dialog then offers to **assign that Task** and set its **initial status** — both pre-filled (you, and your process’s first “in progress”-style status), editable, and skippable in one click with **Skip**; skipping leaves the Task exactly as before this feature existed. If the requested status can’t be applied, the Task is still created and the session still closes — a small warning explains only that one detail. Sessions become **natively queryable** in Azure DevOps. If archiving fails, the session **stays active**, a clear message explains what happened, and the action can simply be retried — retrying **never creates a duplicate Task**. *Abandon* (with confirmation) closes the session without creating anything.
- **Say how the session went, right when you end it** — the closure dialog offers an optional verdict: Passed, Failed or Blocked (the same labels and colours you already know from test results), nothing preselected. Skip it entirely and closure works exactly as before. Once the session is closed, the verdict is **final** — it can't be changed afterwards, on the tab or in the hub. **It never counts toward the report's pass rate, quality score or any other indicator** — it's a note about the session itself, not a test result, and a report built from sessions with and without a verdict looks identical either way. The verdict also travels as a tag (`verdict:passed`, `verdict:failed` or `verdict:blocked`) on the tracking Task it creates, so it can be queried natively in Azure DevOps (sessions closed up to 0.2.6 carry the bare tag `Passed`, `Failed` or `Blocked`, never rewritten: a query looks for both forms) — but that tag is only a mirror: if someone edits it by hand in Azure DevOps afterwards, TestPulse Studio keeps showing what the session itself recorded, never the edited tag.
- **Export the report as PDF, on TestPulse Studio’s own look** — once a session is closed, **Export PDF report** turns it into a shareable PDF with a proper **cover page** (charter as title, your organisation's configured colour and logo — same charter as your test reports, never a fixed TestPulse Studio accent), duration, campaign tag, the full chronological timeline — notes tagged by type (question / idea / anomaly), work items created as **clickable links** straight to their work-item form — and a signature (tester + timestamp) in the footer of every page. Screen captures are **embedded as images** when their file can still be fetched, and simply **listed by name** otherwise — a report never fails to generate. **Export PDF report (US)**, always available from the tab header, gathers **every closed session of the story** into one consolidated PDF. Both open a small **title dialog first**, pre-filled with the charter — validate as-is or adjust it, cancel and nothing is generated. Both follow the active language (FR/EN).
- **Your colour and logo now reach this tab on Azure DevOps Server on-premises too (2.48.0)** — the tab loads instantly with default colours, then applies your organisation's configured branding a moment later once it arrives from your synced preferences. If it can't be retrieved, exports simply use the default branding and a small banner on the tab tells you so — never a silent difference from what you see on other devices.
- **Attach the report to the tracking task** — once exported, **Attach report to task** uploads the same PDF and attaches it to the session’s tracking Task in one click — a manual, explicit action, never automatic on closure.
- **Resilient by design** — every note and capture is autosaved (debounced, \~2 s) to Extension Data, with a brief **“saving…”** indicator while a write is still in flight — so you’re never tempted to reload before it’s actually saved — and saved reliably even across several edits in the same session; closing and reopening the story **restores the active session** with its timer recomputed from the real start time. A save that can’t go through — during creation or autosave — is signalled clearly instead of failing silently; your entries always stay on screen either way. Nothing leaves your Azure DevOps tenant.
- **Permissions** — attaching captures and creating work items require the **work-items write permission**. After updating, an **administrator must re-approve** the extension; until then, a clear banner on the tab explains it instead of a raw error. Reads are unchanged.

The tab is bilingual (FR/EN switch, remembered locally) — including the generated repro steps and session reports, which follow the active language.
