What a project administrator sets, everyone gets — and the rest stays yours.

**Set for the whole project** (read-only in **My preferences**, with a lock — « Set by the project » or « Set by the profile “X” » — and a label saying where the value comes from): pass, warning and flaky thresholds, pass-rate weighting, trend regression threshold, quality scoring, cover page branding (header label, colour, logo), signature sheet structure, which export sections are included (never their order), the run limit, notification channels and generation reminders (those of the project come first, read-only, and yours follow). A setting the project does **not** define stays personal and editable — setting one never confiscates the others.

**Always yours**: interface language, the traceability view you prefer, the order of the report sections, which export formats you are offered, whether empty suites are shown, which panels you keep collapsed, your saved views and templates, the signature **values** you type on a report, and when each of your scheduled reminders last ran.

**Never changes on an archived report**: its figures, its verdict, and the thresholds and scoring it was produced with. They were captured inside the report the day it was generated. Re-exporting a two-year-old report gives the same numbers.

**Follows the branding in force**: how a report *looks* when exported — header label, colour, logo, signature layout, which sections are included. Export the same archived report after the project changes its colour, and the new file carries the new colour, with the same figures inside.

**Quality scoring** belongs to the project and is never changed from My preferences: it is set in the administration, per profile, in *Configuration profiles › Project default › Thresholds and quality*, reserved for project administrators, and *My preferences › Thresholds and calculations* shows it read-only, in the **GO / NO-GO verdict** card.
