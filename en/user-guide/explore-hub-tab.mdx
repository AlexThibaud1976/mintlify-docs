The **"Explore" hub tab** (now the second tab, right after Report) lists every exploratory session across the whole project — no more hunting one story at a time. It is entirely **read-only**.

- **Filter by scope** — area path, iteration path, campaign tag and tester, each populated from what actually exists in the project, plus a period range. A live result count tells filter-narrowed-to-nothing apart from an empty project.
- **Opens on your own sessions by default (2.57.0)** — the Tester filter starts pre-set to your own resolved name, with a visible **"Filtered to my sessions"** chip right next to the filters and a one-click **"Show whole project"** to see everyone's; if you don't appear in the tester list yet (no tracking Task resolved to your name), it starts empty exactly like before. Your own sessions still awaiting their tracking Task (active or abandoned) always stay visible under this default — filtering them out would have hidden the very ones you're looking for. This narrows what you **see**, never what you **can** see: exploratory sessions are stored in your organisation's Extension Data at the **project** scope, readable by anyone with access to the project regardless of Azure DevOps team membership — this filter reduces noise, it is not a privacy boundary.
- **Grouped by story, with a real preview** — each story's row now shows its **cumulative effort** and **last activity** before you even expand it, behind a conventional chevron. Expand it to reveal **one row per session** — status, charter, tester, duration, entry counters and a link straight to its tracking Task when one exists — or, for a still-**active** session with no tracking Task yet, straight to its own work item instead, where the Exploration tab picks the session back up (2.57.2; read-only, it never transfers ownership) — instead of a single blended line for the whole group. Each group also shows its work item **type** at a glance; TestPulse Studio's own session-record Tasks get a distinct marker instead of blending in as an ordinary type — they stay listed, never hidden. The tester on each row is always a **resolved name**, never a raw identity descriptor: it comes from the session's own tracking Task when one exists, or reads as unidentified rather than showing anything technical — **unless the active session is your own (2.58.0)**, in which case your name shows immediately (no tracking Task needed to know that) and its link explicitly offers to resume it; a colleague's active session still reads as unidentified and its link never promises a resume it can't deliver — only your own session can actually be restored.
- **Dated sessions, most recent first (2.68.0)** — every session row now shows when it started, date **and** time in your language, so two sessions run on the same day are told apart without opening either. Inside a story, sessions run from the most recent to the oldest, with any session still **open** at the top — that is the one you came back to finish. The order **between** stories has not changed (most recent activity first). The **period filter** now includes both of the days you pick: asking for *31/08 → 31/08* returns the sessions of 31 August, which it used to leave out. It compares calendar days as you see them on screen, in your own time zone, never an instant in UTC — so a session displayed as 31 August is always returned by a filter on 31 August. The period printed on the aggregated PDF cover follows the same rule and no longer shows the day before the one you picked.
- **A deleted tracking task no longer hides a session (2.68.0)** — when the Task recording a session is deleted in Azure DevOps, the session record itself is untouched: it lives in Extension Data and outlives its materialisation. The hub now keeps such a session in the inventory and says *The linked task is no longer available* on its row, with its **Export** button still there; the previous-sessions list on the story does the same, checking every tracking task in one grouped read when it loads rather than one call per line. Never « deleted » — a deleted work item goes to the recycle bin and stays restorable, so restore it and the link comes back on the next refresh. Behind the hub symptom sat a second cause worth naming: the tester of a session is resolved from its tracking task, and the hub applies a Tester filter **by itself** when it opens, so an unresolved session was quietly dropped from an inventory presented as complete. A filter you **chose** still hides what it must; one applied **for you** no longer removes anything you did not ask it to remove. If the grouped read fails, links render exactly as before — a network incident must never look like a mass deletion.
- **Evidence section in the session report (2.68.0)** — files you drop into a session are uploaded to Azure DevOps as attachments of the work item, but the report only mentioned them in passing. Both the report written into the tracking task and the session **PDF** now end with an **Evidence** section listing every attachment of the session — dropped files and pasted captures alike — with name, time and size, in chronological order; no attachments, no section. The two surfaces do different jobs: the report in the task is a **register**, written once at closing and never revisited, so it cannot honestly claim a file is reachable *now* — it carries **no link**, and real access is one tab away on the same work item. The **PDF** is the access surface, generated on demand and the only one that travels outside Azure DevOps, so that is where the links live. An image you **dropped** stays an attachment line rather than a thumbnail — only pasted captures are embedded. When the PDF is generated, one grouped call reads which attachments are still linked to the task: one that is gone, or whose reference is malformed, is listed without a link and reads *Attachment unavailable*. Never one request per file, and if that call fails nothing is concluded — every link renders as usual.
- **Status at a glance, colour and icon both** — Complete, Active, Abandoned, Interrupted and Incomplete each get a distinct colour **and** icon, never colour alone (readable for colour-blind users and in dark theme too). A session whose closing task exists but wasn't fully recorded is flagged **incomplete**, with a link straight to that task.
- **Verdict, right next to status** — a session closed with a verdict (Passed, Failed or Blocked) shows it as its own badge, next to the status badge, never replacing it; a session closed without one shows no verdict badge at all — never a grey "not set". A **Verdict** filter narrows the list to one value, or to **"No verdict"** specifically, combinable with every other filter. This reads the session's own record, never a tag you might have edited by hand in Azure DevOps afterwards — and it never feeds into any coverage or quality count on this screen or its exports.
- **Honest totals, easy to read** — a summary bar shows requirements covered and how many sessions make up the current filter as prominent numeric values (never grey badges you'd mistake for a filter) — the session count matches the rows on screen exactly, incomplete ones included (2.57.2; replaces a "Discoveries" tile that counted work items created from TestPulse Studio, not actual observations, and was dropped rather than relabelled). The coverage count only counts actual requirement-type work items — never TestPulse Studio's own session-record Tasks — and renames itself honestly if your process makes that distinction impossible, rather than showing a number it can't back up. A "counters possibly lagging" note only appears when an active session is actually on the page you're looking at. Effort totals are gone: a running or forgotten-open session used to make a summed total meaningless, so only each session's own duration is shown (a very short session reads **"&lt; 1 min"**, never a misleading "0 min" or "NaN min").
- **Archived, never deleted** — sessions past a configurable age (6 months by default) are hidden by default; an **"include archived"** toggle brings them back, and the true total is always shown regardless.
- **Built for scale** — paginated, so a project with hundreds of sessions stays fast and readable.
- **Export one session, or the whole scope** — a session with at least one entry (note, capture, file or created work item) gets its own **Export** button right on its row — same PDF report as on the work item, no need to open the story. **Export report**, still in the header, turns the *currently filtered* scope into one consolidated PDF: cover page, the same coverage summary (no "Discoveries" line, removed from the PDF too — 2.57.2), a bar chart of session counts by iteration and by area (never a summed duration a still-open session could distort), a section per user story, and a full appendix — never an execution indicator (this is exploratory testing, not pass/fail). Nothing breaks either export: a session whose content can’t be read is simply skipped, or noted as unreadable rather than silently dropped.

Bilingual (FR/EN) — and, like the rest of TestPulse Studio's exploratory testing surface, nothing leaves your Azure DevOps tenant.
