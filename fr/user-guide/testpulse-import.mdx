**Où.** *Outils › Paramètres* (**Mes préférences**), page **Importer depuis TestPulse**, dans le groupe **Projet** du rail. Chaque membre la voit désormais. L’import lit les données de l’extension TestPulse (éditeur Kisskool) sur l’organisation : **vos données** (portée utilisateur) — préférences, modèles et vues, historique personnel, snapshots du Cockpit — et **les données du projet** (portée projet) — rapports publiés, barème, champs de dérive, paliers, source des bugs, sessions exploratoires. Aucune IA n’intervient.

**La lecture, par un jeton.** Studio essaie d’abord une lecture directe, mais Azure DevOps refuse qu’une extension lise les données d’une autre, et l’écran le dit : « TestPulse est installée, mais sa lecture directe est refusée par Azure DevOps ». **Le chemin normal est donc un jeton d’accès personnel**, à portée « Extension data (read) » seulement : créez-le par le lien **Créer un jeton « Extension data (read) »**, collez-le dans l’écran, puis **Lire avec ce jeton**. Le jeton sert à cette lecture et à elle seule : gardé en mémoire de l’écran, il n’est jamais enregistré ni journalisé, et il est effacé après la lecture et à la fermeture de l’écran.

**L’aperçu.** Pour chaque ensemble : son origine, sa destination dans Studio, son statut, ses éléments, sa taille et la règle **Si déjà présent** — *Conserver l’existant* (par défaut), *Remplacer*, *Conserver les deux* ou *Ignorer les doublons* ; les préférences et les réglages uniques ne proposent que conserver ou remplacer. Des modèles et des rapports, seuls les **noms** s’affichent, jamais leur contenu. **Rien n’est coché par défaut** : cochez les ensembles un à un, ou utilisez **Tout sélectionner (vos données)** / **Tout sélectionner (projet, administrateurs)**. **Importer la sélection** reste grisé tant que rien n’est coché. Les ensembles du projet sont **réservés aux administrateurs du projet** : un membre les voit listés, non sélectionnables, avec la raison. Quand **Préférences** est coché, l’option **Dans vos préférences** montre les webhooks et les rapports programmés, avec leur nombre, décochés par défaut — un webhook envoie des messages, un rapport programmé se génère seul ; décocher Préférences les décoche aussi.

**L’écriture.** **Importer la sélection** écrit dans TestPulse Studio seulement : **TestPulse n’est jamais modifiée**. L’import se rejoue sans doublon : un élément déjà importé est reconnu à son origine. Le quota de stockage est vérifié avant toute écriture : s’il devait être dépassé, rien n’est écrit. Les modèles, les webhooks et les rapports programmés sont ignorés quand Studio n’a pas encore de préférences où les poser (« aucune préférence Studio où les poser ») ; la « dernière version vue » de TestPulse n’est jamais reprise. La source des bugs du projet devient le réglage **Source des bugs** de Studio. Un élément dans un format plus récent que ce que Studio connaît est mis de côté, jamais deviné.

**Le compte rendu.** Pour chaque ensemble : écrits, conservés, ignorés, illisibles et en échec, avec leurs raisons ; un ensemble vide figure « 0 — vide ». Les rapports importés portent « Importé de TestPulse x.y.z » dans l’Historique. Rechargez TestPulse Studio pour voir les éléments importés.
