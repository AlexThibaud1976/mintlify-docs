L’onglet **« Couverture »** apparaît sur une fiche **User Story / PBI** (placé automatiquement, monté au premier clic). Il est en **lecture seule** et indépendant des rapports publiés.

- **Bandeau** — deux pastilles, **Couverture** (des cas de test sont-ils liés ?) et **Profondeur** (ces tests ont-ils de vraies étapes ?), affichées instantanément.
- **Détail** (chargé automatiquement) — un **verdict d’exécution** (**Réussi / Non OK / Non exécuté / Non couvert**), l’analyse de profondeur, une synthèse chiffrée, et le pass/fail le plus récent de chaque test lié avec le **bug** derrière un échec.
- **Dernière exécution config-correcte** — quand un cas de test couvre **plusieurs US sœurs qui ne diffèrent que par la configuration** (ex. Italie / Singapour / Corée), la **« Dernière exéc. »** affichée ici est résolue depuis **la configuration de cette US** (sa requirement-based suite), jamais le run plus récent d’une US sœur. Une US sans requirement-based suite garde le comportement précédent (dernière tous configs confondus). Le **lien run** ouvre désormais le **résultat exact** (quand connu) ; les libellés du sélecteur de portée s’affichent en **« plan · config »** quand une configuration est connue.
- **Sélecteur de portée** — le **sélecteur de portée** s’affiche **dès que la fiche est couverte** : **Dernière (tous plans)** (défaut) ou un **plan de test précis**. Il cadre le pass/fail sur la portée choisie (masque les tests hors plan), est mémorisé par fiche et bascule **instantanément en mémoire** (aucune lecture nouvelle). Avec un seul plan, il affiche quand même *Dernière (tous plans)*, si bien que les résultats sont toujours explicitement cadrés sur la **dernière exécution**.
- **#ID cliquable** — chaque test lié affiche un **#ID cliquable** qui ouvre le **cas de test** (work item) dans un nouvel onglet.
- **Colonnes triables** — cliquez n’importe quel en-tête (**#, Test, Outcome, Last run, Bug**) pour trier le tableau ; re-cliquez le même en-tête pour inverser le sens. Outcome trie attention en tête (échecs d’abord), Test par nom. Votre tri est mémorisé par fiche et l’ordre par défaut reste inchangé.
- **Ouvrir le run / le plan** — une ligne **exécutée** affiche un seul lien qui ouvre son **run de test** (colonne Last run) ; quand un **plan précis** est cadré, un lien **Ouvrir le plan** s’affiche à côté du sélecteur de portée et vise la **suite exactement exécutée** quand elle est dérivable (jamais une page de plan vide). Les deux passent désormais par Azure DevOps lui-même plutôt que par le popup natif de l’onglet, donc s’ouvrent aussi de façon fiable dans la fiche work item sandboxée on-prem (fini l’onglet blanc sur ADO Server on-prem) ; ils s’ouvrent dans un nouvel onglet et sont des navigations portail (aucune lecture nouvelle).
- **Modifiée après le dernier run** — quand la fiche a été **modifiée après l’exécution la plus récente de ses tests liés**, un badge d’avertissement conditionnel s’affiche en tête du panneau. Il est calculé sur **tous** les résultats (plan-indépendant, comme le bandeau), n’apparaît jamais pour une fiche jamais exécutée, et disparaît dès qu’un run plus récent existe. Mêmes données que celles déjà lues par l’onglet — aucun appel ajouté.
- **Ce qui a changé depuis le dernier run** — le bandeau ci-dessus porte désormais un bouton **« Afficher le détail »**. Le déplier va chercher (une fois, en lazy — jamais au chargement de la fiche) les modifications de l’US depuis ce run et liste les **champs métier** impactés (Critères d’acceptation, Description, État, Priorité, Itération, Tags — et Titre) en **avant → après**, avec **l’ajout surligné** sur les champs riches (un petit word-diff maison, sans dépendance) et un badge **« Alimente la profondeur »** sur les changements de Critères d’acceptation / Description. Un bloc distinct liste les **pièces jointes ajoutées/retirées** depuis le run. Replier puis redéplier ne relance jamais l’appel.
- **Sessions exploratoires mentionnées (2.58.0)** — quand cette exigence porte une ou plusieurs sessions exploratoires **closes**, l’analyse de profondeur gagne une ligne informative indiquant leur nombre exact, nommant l’onglet **Exploration** (juste à côté de celui-ci — Azure DevOps ne permet pas à une extension d’y basculer par programme, la mention le nomme donc au lieu d’y conduire). Elle ne touche jamais la pastille **Couverture**, le verdict d’exécution, le taux de réussite ni le score qualité — une exploration n’y crédite rien, volontairement ; elle indique seulement que l’exigence n’était pas non testée, seulement pas testée *par un cas de test*. Chargée en arrière-plan, une fois les pastilles et le verdict déjà affichés — un échec de lecture omet simplement la ligne, jamais un « 0 » qui affirmerait qu’aucune exploration n’a eu lieu.

Couverture, Profondeur et la liste des bugs restent plan-indépendantes. Aucun nouvel appel, scope ni dépendance au-delà de celui décrit ci-dessus ; aucune écriture.
