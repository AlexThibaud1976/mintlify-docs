**Où.** **Lire le code** se trouve à l’étape 0 **Exigence** de **Design** et dans l’onglet **Exigence** d’un work item. Rien n’est lu à l’ouverture.

**Avant.** Votre organisation approuve une fois les autorisations du code (un administrateur de l’organisation, dans Paramètres de l’organisation › Extensions), et un administrateur du projet coche **Extraits du code source** dans les données envoyées au modèle (*Assistant IA › Fonctions et données*) — décochée par défaut ; coupée, Studio ne fait aucun appel au code.

**Ce qui est lu.** Les pull requests, commits et branches liés à l’US et à ses tâches enfants (Azure Repos ; les liens GitHub ne sont pas lus dans cette version). Chaque lien dit ce qui a été lu (titre et état d’une pull request, dépôt, nombre de fichiers) ou pourquoi il ne l’a pas été : l’organisation n’a pas encore approuvé la lecture du code, vous n’avez pas accès au dépôt, dépôt ou version introuvable.

**Avant l’envoi.** La liste montre chaque fichier — dépôt, version, catégorie (validateurs, routes, écrans, tests, autres), entier ou parties modifiées, taille, tokens, le lien qui l’a amené — et le total estimé. Décochez ce qui ne doit pas partir. Verrous, fichiers générés, minifiés et binaires sont toujours exclus ; **un fichier secret n’est jamais proposé**. Les plafonds (fichiers, caractères par fichier, au total) se règlent dans **Exigences et conception**.

**Ensuite.** Les fichiers cochés rejoignent la prochaine évaluation de l’exigence : les critères qui dépendent du code peuvent être vérifiés. Rien n’est gardé une fois la page fermée. **Confronter au code** arrive dans une prochaine version. Azure DevOps Server : la lecture du code n’est pas validée.
