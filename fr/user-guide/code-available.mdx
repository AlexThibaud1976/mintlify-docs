**Quoi.** Une fois la conception des tests d’une exigence écrite dans Studio, Studio retient les liens de développement de l’US et de ses tâches enfants (pull requests, commits, branches). Quand de nouveaux liens apparaissent, il vous dit que **du code est disponible** — **sans IA**, à partir des seuls liens du work item : le contenu du code n’est pas encore lu. Une conception écrite avant cette version est suivie aussi : la référence est reconstituée d’après la date à laquelle les cas de test ont été liés à l’US, et un lien qui pouvait déjà exister n’est jamais signalé.

**Couverture.** La colonne **Code lié** affiche « ● Code disponible depuis la conception du &lt;date&gt; · 1 PR, 4 commits », « aucun lien de développement nouveau » ou « non suivi : aucune conception écrite ». Elle est calculée pour les exigences affichées, après l’analyse, sans faire attendre la page (« … » d’abord). Les liens GitHub sont listés « non lus (V1) ». **Avec code nouveau (n)** ne garde que ces exigences ; la pastille ouvre l’exigence dans **Design**.

**Design et l’onglet Exigence.** À l’ouverture de l’exigence, le même bandeau dit depuis quand du code est disponible ; Design liste aussi les liens nouveaux — le lien, le work item qui le porte, « dépôt Azure Repos » (son identifiant en infobulle), la date de liaison.

**Ignorer ces liens.** Masque la pastille pour tout le projet jusqu’à l’arrivée d’un autre lien ; qui a ignoré et quand restent affichés, avec **annuler**. **Confronter au code** est affiché désactivé tant que votre organisation n’a pas autorisé la lecture du code.
