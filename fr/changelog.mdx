<Update label="0.1.162" description="2026-10-12">

Automated tests: screen limits followed through the Page Object; pytest-bdd case read from its step definitions; the
application root cited "/" is never a marker (TPS-250).

- **Screen limits through a Page Object**: the model bench (gpt-6-sol, Playwright TS, TC 3055) showed a test "ready to
  review" three times out of three although iteration 2 types 21 characters into a field limited to 20 — red when run.
  The test called `po.fillAddress(row.codePostal, row.telephone, row.rue)` and the method typed `phone` into
  `getByTestId("phone")`: replacing the parameter by the value of the call also rewrote the selector string, so the field
  was no longer found. The parameter is now replaced in the code only; the argument of rank n (or named, Python / C#) is
  the value of the parameter of rank n (or of that name), in TS / JS, Python, Java and C#. The check of ignored data
  follows the call too: data passed to a method that never reads it, or replaces it with a fixed value, is marked.
- **pytest-bdd "without a usable result"** (gpt-5.4, three runs out of three, the case asked again included): in BDD
  the `tests` entry of a case carries nothing; a case left out of it (or `tests` left out) whose step definitions bind
  its scenario is now read from its definitions and noted in **Log and failures**. Also read: an identifier written like
  the tag (`tc_3056`, `@tc:3056`), `code` returned as an object, the keyword `@given`.
- **Citation "/"** (Selenium, gpt-5.4 and gpt-6-sol): `driver.get(baseUrl + "/")` with the citation "/" was marked
  "converted into markers". A citation designating the root (`/`, `baseUrl`, `baseUrl + "/"`) that is not found is now
  the application root, shown as such under **Citations returned by the model**.

</Update>

Automated tests: no more false “ready to review”, the assistant’s markers sorted, Selenium inline; code check
proposals contradicted by their own citations discarded (TPS-239).

- **Never ready with a broken file**: a syntax error in a file of a test (its own, the Page Object it calls, the step
  definitions) marks it “syntax error”; a step whose body has no statement (comments, `pass`, a lone `return`) is not
  mapped — the pytest-bdd case where five step definitions held only `# todo: …` is a skeleton again.
- **The assistant’s markers**: `# todo`, `// TODO`, `# FIXME`, “to complete” become Studio markers. On a complete step
  (its citations found, no built value) the assistant’s remark becomes a non-blocking **review note**, counted apart.
  The instructions say when to mark: only a missing selector, route, message or value; an empty value is a value.
- **Other language**: the JavaScript Playwright API in a Python file (`getByTestId`, `toHaveText`, `toBeVisible`) and
  the Python one in Java, C# or JavaScript files are marked.
- **Selenium**: actions inline (`driver.findElement(By…)`, `wait.until(…)`), no Page Object suggested; the test
  declares `wait`.
- **Code check**: a proposal contradicted by another of its citations (a README line counts) is discarded; a “rule
  from the code” that the cited code contradicts (“the `L-` prefix is not accepted”, “8 to 20”) is discarded, never
  shown as taken from the code.

Conception, step 0 of an assessed requirement: one decision, one screen (TPS-240).

- **The page fits**: the requirement is named once (#id · title, then type, state, revision and *Change requirement*);
  *Existing coverage* is one line as soon as an assessment exists (“N linked tests · per technique · matches”), folded
  and remembered for you and this requirement; generation settings and *What goes to the model* leave step 0.
