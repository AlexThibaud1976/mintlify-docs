Les versions ci-dessous sont celles de **TestPulse**, l'extension dont TestPulse Studio est issu — pas celles de TestPulse Studio, dont les jalons sont dans l'onglet **Nouveautés**. Le widget de dashboard qu'elles mentionnent ne fait pas partie de TestPulse Studio.

**v2.61.1 — 2026-08-19**
- Corrigé : le bandeau de mise à jour du hub pouvait afficher des astérisques Markdown à nu et s'étaler sur quatre lignes — il reprenait tel quel le texte de l'item du panneau Nouveautés, un champ écrit pour la documentation, pas pour une ligne de bandeau. Une phrase de bandeau dédiée et optionnelle le remplace ; absente dans la langue courante, elle n'affiche aucune deuxième ligne plutôt que de basculer vers l'autre langue ou vers ce texte d'item. Le panneau Nouveautés lui-même est inchangé.

**v2.61.0 — 2026-08-19**
- Repository : la source d'amorçage « Plans & suites » est retirée — Area Paths est désormais l'unique source, le dialogue ouvre donc directement sur l'aperçu chiffré et la confirmation, sans sélecteur de source. Sur un projet réel très chargé en plans, la source plans/suites produisait un arbre plusieurs fois plus encombré qu'Area Paths, au prix de bien plus de requêtes, et un arbre à parent unique ne peut structurellement pas refléter des plans qui partagent leurs cas — optimiser ces requêtes aurait produit le même arbre encombré. Rien de ce qui en a déjà été amorcé n'est touché. Le Coverage Builder n'est pas affecté — il partage l'appel de résolution des suites sous-jacent, strictement inchangé.
- Repository : quatre évolutions pour laisser respirer l'arbre. Les actions de ligne (renommer, ajouter, supprimer, générer un plan) restent désormais masquées tant que vous ne survolez pas, ne sélectionnez pas, ou ne focalisez pas la ligne au clavier, avec leur espace toujours réservé pour ne jamais décaler la mise en page à l'apparition. Les noms de dossier longs se tronquent sur une ligne avec le nom complet en infobulle plutôt que de passer à la ligne. Un séparateur glissable et ajustable au clavier (borné, mémorisé par utilisateur) permet de redimensionner l'arbre face à la liste des cas. Sans sélection, l'arbre occupe toute la largeur au lieu d'un panneau « 0 selected » qui mangeait la moitié de l'écran.

**v2.60.1 — 2026-08-19**
- Bandeau de mise à jour du hub : un petit bandeau d'information au-dessus de vos rapports nomme la nouvelle version et renvoie vers Nouveautés dès qu'un major ou un minor arrive (silencieux sur un simple patch, y compris celui-ci — aucune version de lancement ne peut l'afficher pour elle-même). Le fermer est propre à chaque utilisateur (ADO Extension Data, scope User) et n'affecte jamais les autres membres du projet. Aucun appel ADO ni dépendance supplémentaire.

**v2.16.3 — 2026-06-26**
- Corrigé (suite de la 2.16.2) : le widget de dashboard « Quality overview » et sa blade de configuration se chargent désormais sur Azure DevOps Services. Les ids de contribution pleinement qualifiés sont maintenant enregistrés avant l'init du SDK, donc disponibles au moment du lookup unique de l'hôte cloud — le ré-enregistrement post-handshake de la 2.16.2 arrivait trop tard. L'enregistrement par id court (on-prem Server 2022.1) et le log diagnostic restent inchangés. Aucune nouvelle dépendance, aucun appel/scope ADO, manifeste inchangé.
- 741 tests Vitest (4 nouveaux)

**v2.16.2 — 2026-06-26**
- Corrigé : le widget de dashboard « Quality overview » se charge désormais sur Azure DevOps Services. L'hôte cloud résout les contributions par leur id pleinement qualifié ; après le handshake SDK, le widget se ré-enregistre sous cet id exact (en plus de l'id court). Ceinture + bretelles, purement additif — l'enregistrement par id court est inchangé, donc le chemin on-prem (Server 2022.1) n'est pas affecté. Un log diagnostic indique l'id de contribution résolu. Aucune nouvelle dépendance, aucun appel/scope ADO, manifeste inchangé.

**v2.15.0 — 2026-06-24**
